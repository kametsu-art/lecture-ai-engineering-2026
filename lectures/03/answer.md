## 宿題

- 取り組んだレベル：基礎
- やったこと：
  - 実験A：`app/tools.py` の `search_glossary` の docstring を「query には調べたい用語を1つだけ入れる（例: "LoRA"）」→「まとめて入れる（例: "LoRA QLoRA"）」に変え、「LoRAとQLoRAの違いは？」で比較（変更後は2回実行）
  - 実験B：`app/agent.py` の INSTRUCTIONS から「必ず search_glossary で用語集を確認する」の1行を削除し、「AIE2026の講座の宿題にある「3レベル」とは何ですか？」で比較（変更後は2回実行）
  - 実験C：Bで変化が出なかったため、モデルが自力で答えられる一般用語「LoRAとは何ですか？」で、削除あり／なしを比較
  - 一度に1か所だけ変え、実験ごとに `git restore` で元に戻した。すべて `--trace` 付きで実行し、ログは `hw03/` に保存

- 結果：

  | 実験 | 条件 | ツール呼び出し | requests / tool_calls | 入力トークン |
  |---|---|---|---|---|
  | A | 変更前（1つだけ） | `'LoRA'`, `'QLoRA'` | 2 / 2 | 1196 |
  | A | 変更後（まとめて）×2回 | `'LoRA QLoRA'` | 2 / 1 | 891, 891 |
  | B | 変更前 | `'3レベル'` | 2 / 1 | 783 |
  | B | 1行削除 ×2回 | `'3レベル'` | 2 / 1 | 735, 735 |
  | C | 変更前 | `'LoRA'` | 2 / 1 | 941 |
  | C | 1行削除 | `'LoRA'` | 2 / 1 | 893 |

  - A：docstring に従って検索が1回にまとまり、tool_calls は 2→1 になった。requests は2のまま。回答はどちらも用語集の定義に沿っていた。同じ検索語なら検索結果も同じになるため、入力トークンは2回とも 891 で一致した（揺れたのは出力のみ）
  - B・C：1行を削除しても、講座固有の質問（B）でも一般用語の質問（C）でも検索は続いた。入力トークンが毎回48減っており、削除が反映されていることは確認できた
  - C では、削除なしの回答が用語集の言い回し（「2つの小さな行列の積」「PEFT手法」）に近く、削除ありの回答は「巨大なAIモデル」「省メモリ」など一般的な説明が多かった（1回ずつなので傾向にとどまる）

- 気づき・疑問：
  - **「1つずつ検索させる」の代償は、LLM 呼び出し回数ではなくツール結果のトークン量に表れた。** `search_glossary` を API なしで直接呼んで確認すると、`"LoRA"` で3件（LoRA・ランク（LoRAのr）・QLoRA）、`"QLoRA"` で2件（QLoRA・LoRA）が返り、計5件のうち2件が重複していた。`"LoRA QLoRA"` では重複のない2件だった。この検索は空白を除いたうえで用語名が検索語に含まれるかを見る部分一致で、もともと近い用語を一緒に返す。そのため「1つずつ」の指示はかえって重複を生んでいた
  - ただし `MAX_RESULTS = 3` なので、4語以上をまとめると落ちる用語が出るはずである。**docstring の良し悪しは文面だけでは決まらず、ツールの実装（検索方式・件数の上限）とセットで決まる**
  - INSTRUCTIONS の「必ず検索」と docstring の「答える前に使うこと」は、同じ指示が2か所に書かれていた。片方を消しても、もう片方が動作を保った。docstring はツールのすぐ近くに置かれた説明としてモデルに渡るので、「ツールを使うかどうか・どう使うか」には全体への指示より強く効くのではないか
  - 疑問：削除した1行は「検索するか」ではなく、「検索結果にどれだけ忠実に答えるか」に効いているのではないか（C の言い回しの差）。試行回数を増やすか、INSTRUCTIONS は残したまま docstring の「答える前に使うこと」を消す実験で切り分けたい。
